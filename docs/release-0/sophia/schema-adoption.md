# Schema adoption

Additive columns/tables this feature introduced to the bills schema, for anyone reviewing or extending it.

- `bills.end_date` — nullable `TEXT` date; a bill/subscription with an end_date stops projecting occurrences and is reported as "paid, Ended {date}" once it's passed.
- `bills.source` — `TEXT NOT NULL DEFAULT 'manual'`, CHECK-constrained to `manual`, `f3_handoff`, `f4_handoff` or `chat`; flags where a bill came from. **Flagged loudest**: `f4_handoff` rows are created with `confirmed_at=NULL` and surface an "Added from Spending Alerts — keep it?" prompt until the user acts on them (reworded from the original "Confirm this?", which did not say where the row came from).
- `bills.confirmed_at` — nullable `TEXT` date; distinct from `created_at`, marks when the user actually confirmed a bill (used for the "barely using" chat question and the confirm-prompt above).
- `chat_messages` — new table backing the Ask Tally chat history and its audit trail. Columns: `id`, `role` (`user`/`assistant`, CHECK-constrained), `content`, `op_json` (the proposal, if any), `applied` (`INTEGER NOT NULL DEFAULT 0`), `created_at`.
- `suggestions` (added 2 Sep 2026, PR #105) — new table holding an AI proposal between the moment the model makes it and the moment the user decides on it, so nothing the assistant suggests is ever written straight through. Columns: `op` (`create`/`update`/`delete`), `entity` (`bill`/`payment`/`dispute`), `entity_id`, `payload_json`, `status` (`pending`/`applied`/`rejected`/`failed`, default `pending`), `error`, `message_id` referencing `chat_messages(id)` `ON DELETE SET NULL`, `created_at`, `resolved_at`. Approval claims the row atomically (`pending` → `applied`) before applying it, so two approvals cannot both spend one suggestion; a failure lands as `failed` with `error` set and nothing changed.
- `bills.exclude_from_plan` (decision D, added 22 Aug 2026) — `INTEGER NOT NULL DEFAULT 0`; seeded `1` for Rent only. The calendar card's month breakdown is the *only* consumer that filters on it (bills with it set never enter that particular `month_breakdown()` call); the chat "total" answer and `/api/upcoming`'s `monthly_committed_cents` keep including everything, unfiltered. Never matched on the bill's name — it's an explicit flag, not a "Rent" string check.
