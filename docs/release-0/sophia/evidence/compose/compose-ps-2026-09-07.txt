================================================================================
Backends through the shared shell on :3000
================================================================================

$ for f in bills transactions anomalies budgets savings; do
    curl -s -o /dev/null -w "%{http_code} %{url_effective}\n" "http://localhost:3000/${f}-backend/"
  done
404 http://localhost:3000/bills-backend/
200 http://localhost:3000/transactions-backend/
200 http://localhost:3000/anomalies-backend/
200 http://localhost:3000/budgets-backend/
200 http://localhost:3000/savings-backend/

Nine of ten are 200. The one 404 is NOT a proxy failure, and this was checked
rather than assumed. The Bills Flask app registers no route at `/` — it serves
`/health`, `/api/*` and `/ui/*` only — so a bare root request 404s at the
application, identically whether it arrives through the shell or directly:

$ curl -s -o /dev/null -w "%{http_code} %{url_effective}\n" http://localhost:5005/
404 http://localhost:5005/

The `/bills-backend/` proxy mapping itself is sound. Any real route behind it
returns 200 through the shell:

$ curl -s -o /dev/null -w "%{http_code} %{url_effective}\n" http://localhost:3000/bills-backend/health
200 http://localhost:3000/bills-backend/health
$ curl -s -o /dev/null -w "%{http_code} %{url_effective}\n" http://localhost:3000/bills-backend/api/bills
200 http://localhost:3000/bills-backend/api/bills

The other four backends do define a `/` route, which is the only reason they
answer 200 at their root. The difference is an API-surface convention, not a
deployment fault, and it is left as-is: adding a root route would be a product
change, and this pass is evidence-only.

`"ok":true` is the string the CI job greps for. `"ollama":"up"` confirms the
backend reaches the composed `ollama` service (compose sets
OLLAMA_URL: http://ollama:11434, overriding config.py's host.docker.internal
default). `"today":"2026-08-20"` is the pinned DEMO_TODAY fixture, not a clock
reading. `"transactions_api":"stub"` is expected: TRANSACTIONS_DB_API_URL is
deliberately unset for Bills.
