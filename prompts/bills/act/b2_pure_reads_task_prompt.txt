**What B2 is.** `status` (paid / due / overdue) is *derived* by
`engine/status.derive_status()` from cadence, dates and payments. The DB
column is only a cache — yet today the read paths keep it fresh by writing:
`services/bills.list_bills()` issues a PUT to :6005 for every row whose
stored status drifted, on every page load, and `get_bill()` does the same.
GETs with side effects, N extra round-trips, and the reason
`services/bills.py` sits at 76 % coverage. After B2: **reads compute and
never write; the cached column is refreshed only where a write already
happens.** This is the last planned code change before the freeze.

## Phase 2 — test-suite consolidation (separate branch, separate approval)

**Goal:** fewer files and fewer test functions, identical coverage.
Coverage is the hard constraint, count the soft one.

Read-only assessment first: map tests per file and the overlaps (three
route files drive the same fake store; the four engine files plus
`test_money` are case tables in prose form). Save the baseline — total %,
per-file %, the exact `term-missing` line sets. **No line covered today may
become uncovered.** Only true duplicates (two tests that cannot fail
independently) may be removed; everything else is merged or parametrised.
Know the counting quirk: pytest counts each parametrised case as one test,
so the reported count only falls by removing duplicates and folding one
scenario's multi-step sequence into one test — never by bundling unrelated
behaviours.

If meaningful reduction is possible, restructure into three modules:
`test_engine.py` (classes per engine module, parametrised tables),
`test_db_api.py` (CRUD, child tables parametrised over the symmetric
endpoints, validation), `test_backend.py` (JSON API, fragments, AI and
contracts). Shared fixtures stay in `conftest.py`; tests cited elsewhere by
name keep their names. Acceptance: suite green · coverage ≥ baseline ·

lossless. Run it only after B2 merges and only if time remains before the
